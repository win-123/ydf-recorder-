## 录制变量（分支 feat/recording-variables）

- 用户澄清核心诉求：A 用户提交、B 用户审核不是同一人，做变量是为了在审核列表里精准找到 A 提交的那条数据；之前写死的值因两个页面列表顺序、列集合、单据状态不同而中断。
- 结论：变量值必须外置且在**录制期固化**，不能用 `{{random.*}}`（`_generated_values` 是 case 级、每 case 新建 executor）或 capture（`RuntimeVariableContext` 是 suite 级且不跨进程）。ydf-browser 0.1.44 的 `--vars-file` 在 `load_dsl_document` 加载期一次性展开整份 DSL，是唯一可靠的跨用户/跨运行链路。
- vendor 同步到 ydf-browser 0.1.44，保留本项目的 Windows 诊断目录与会话复用补丁。
- 实现：新增 `parameterize.py`（值位置白名单、定位键不动、同名值全链路一致、录制期生成唯一默认值、已有变量文件跨文件复用、选行 match 语义诊断）；CLI 新增 `--param-field` / `--param-value` / `--param-map` / `--param-set` / `--vars-output` / `--vars-fresh` / `--vars-plain`（旧 `--parameterize-*` 作为别名保留）；GUI 增加业务主键映射与共享变量文件输入；README 补跨用户用法。
- 验证：全量 229 个测试通过（基线 201 + 新增 28）。A 提交段（8 步）与 B 审核段（4 步）DSL 均通过 `ydf_browser.load_dsl_document` 校验，录入/查询/选行/capture 四处引用同一个 `{{project.name}}`，共享变量文件值在两次录制间保持一致。
- 待办：拿一份真实「一级项目管理」`events.json` 做端到端回放验收；阶段 2 可考虑把 A/B 两段合并成一个 suite 两个 case（`case.user` 切换账号），或补 `table.assert_row_values` 注入。
